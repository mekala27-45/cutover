# Architecture

The criteria are hashed before scoring so a result cannot redefine success. A word and character TF-IDF floor establishes a measured comparison before an encoder earns deployment. Every arm emits the same validated prediction shape; code owns the final action.

Feature and Label are separate immutable records. Arms receive only Feature. Splits follow the date received, and later exact or near duplicates are removed. This models an arriving inbox more closely than a random split.

The incumbent is recorded for evaluation. Live uncertainty reaches a person instead of calling it. Safety escalation is outside the model and takes priority over a confident queue score. No action can close a complaint.

The API reads release state and consumes a client budget in the same transaction that writes its receipt. A response is returned after commit. The API role may read release state but cannot change it. Only an Actions writer may set the kill switch. The initial service has no fitted model and explicitly reports guard_only.

Public NHTSA records stand in for a fictional customer inbox. A real engagement would add a data processing agreement, analyst label review, ticketing integration, a security review and an on-call owner. Those activities have not been claimed.

The public site uses static pages and an aggregate evidence manifest. No complaint text or individual case record is included in its build. Source collection and training run in isolated Actions jobs; published output passes an aggregate allowlist.
